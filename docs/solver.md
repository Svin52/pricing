# Решатель `airprice`: равновесные цены двух авиакомпаний

Программа считает, какие цены будут ставить две авиакомпании на одном рейсе, если каждая
максимизирует свою выручку и учитывает ответ конкурента. Метод — обратная индукция
(динамическое программирование). На выходе: оптимальная ценовая стратегия обеих компаний
для любой ситуации и их выручка.

## Быстрый старт

```bash
pip install -r requirements.txt          # numpy, scipy (+ pytest для тестов)
python -m airprice examples/base.json    # точный спрос
python -m airprice examples/base_poisson.json --mc 20000   # случайный спрос + проверка Монте-Карло
python -m pytest -q                      # тесты
```

Пример вывода для `examples/base.json` (по 50 мест, 20 периодов, 24 уровня цены от 3000 до 14500):

```
Ожидаемая выручка: A = 478 500   B = 446 000

  период  ход    цена A    цена B  места A  места B  спрос A  спрос B  прод. A  прод. B
       0    -     14500     14500       50       50        0        0        0        0
       1    A      9000     14500       50       50        4        0        4        0
       2    B      9000      8500       46       50        3        3        3        3
       ...
       9    A     10500      8500       25       29        2        3        2        3
       ...
      17    A      9500     10000        9        6        3        2        3        2
```

Читается так: в T₁ компания A сразу уходит с 14 500 на 9 000, B в T₂ отвечает 8 500
(чуть дешевле, потому что B менее привлекательна для пассажиров). Когда у A остаётся меньше
мест, чем у B, A поднимает цену до 10 500. Ближе к вылету B тоже поднимает, а A, у которой
мест осталось мало, снижает цену, чтобы распродать остаток.

## Правила модели (по задаче «Код», issue #8)

| Правило | Как в коде |
|---|---|
| Метки T₀ < T₁ < … < T_N, период k = [T_k, T_{k+1}), T_N — вылет | `N = n_periods` |
| 24 уровня цены, одинаковые у обеих компаний | `prices`, цена задаётся индексом уровня 0..23 |
| В T₀ обе компании стоят на одной цене | `start_price`: `"max"` (по умолчанию, как в issue), `"min"` (как в записке) или номер уровня |
| В T₁ первой ходит A, дальше по очереди | A ходит в нечётных узлах, B в чётных |
| Назначенная цена держится до следующего хода этой же компании | то есть два периода |
| Спрос в периоде известен при каждой паре цен | `demand_a[k, iA, iB]`, `demand_b[k, iA, iB]` |
| Компания, распродавшая билеты, уходит с рынка | спрос на соперника берётся из `mono_a` / `mono_b` |
| Непроданные к вылету билеты сгорают | выручка от них 0 |
| При равной выгоде берётся меньшая цена | допуск на погрешность вычислений `tol` |
| Цель — выручка (издержек на место нет) | «прибыль» в issue = выручка |

Дополнительно пришлось решить то, о чём в issue не сказано:

* **Спрос больше остатка мест.** Продаётся `min(спрос, остаток)`, лишние покупатели уходят
  и к конкуренту не перетекают (как в аналитической записке).
* **Что компания знает при ходе.** Остатки мест обеих компаний и текущую цену соперника.
* **Распродана ли компания** определяется на начало периода: если у B к началу периода 0 мест,
  весь период для A действует спрос `mono_a`.

## Два режима спроса

* **`exact`** — спрос точный, как в issue: в таблице целое число покупателей. Траектория цен
  однозначна, и выручка равна сумме по ней.
* **`poisson`** — спрос случайный, как в записке: число желающих купить у A распределено по
  Пуассону со средним из таблицы (у B аналогично, независимо). Выручка — ожидаемая.

Таблицы можно задать **своими** (`"type": "table"`) или **сгенерировать по MNL** (`"type": "mnl"`).

### Откуда берётся спрос в режиме MNL — на примере

Пусть за период приходит 8 человек, привлекательность A = 4,5, B = 4,2, чувствительность
к цене β = 0,0005. Цены: A — 9 000, B — 8 500.

* полезности: u_A = 4,5 − 0,0005·9000 = 0, u_B = 4,2 − 0,0005·8500 = −0,05, отказ = 0;
* e^u: 1, 0,95, 1 → сумма 2,95;
* доли: A — 1/2,95 = 34 %, B — 32 %, не полетят — 34 %;
* спрос: A — 8·0,34 ≈ 2,7 → **3** человека, B — 8·0,32 ≈ 2,6 → **3** (в `exact` округляется).

Если B распродана, она выпадает из выбора: доля A = 1/(1+1) = 50 %, спрос 4 человека.
Это и есть `mono_a`.

## Формат сценария (JSON)

```json
{
  "name": "Базовый сценарий",
  "prices": {"min": 3000, "max": 14500, "levels": 24},
  "capacity": {"A": 50, "B": 50},
  "periods": 20,
  "start_price": "max",
  "demand": {
    "type": "mnl",
    "mode": "exact",
    "arrivals": 8,
    "alpha": {"A": 4.5, "B": 4.2},
    "beta": 0.0005
  }
}
```

* `prices` — либо `{"min", "max", "levels"}` (равномерная сетка), либо явный список цен по возрастанию.
* `capacity` — число мест (одно число — одинаково для обеих).
* `periods` или `times` — число периодов или сами метки T₀…T_N (N+1 число).
* `demand.type = "mnl"`:
  * `arrivals` — покупателей за период: одно число или список длины N;
    либо `arrival_rate` (покупателей за единицу времени) вместе с `times`;
  * `alpha.A`, `alpha.B`, `beta` — числа или списки длины N (можно менять по периодам);
  * `mode` — `"exact"` или `"poisson"`.
* `demand.type = "table"`: `"file": "имя.npz"` с массивами `demand_a (N,24,24)`,
  `demand_b (N,24,24)` и необязательными `mono_a (N,24)`, `mono_b (N,24)`.
  Если `mono_*` не заданы, берётся спрос при цене конкурента на самом высоком уровне —
  ближайшее к «цене +∞», что есть в таблице. Пример: `examples/make_table_example.py`.

## Использование из Python

```python
from airprice import load_scenario, mnl_scenario, solve, play, format_path, monte_carlo

sc = load_scenario("examples/base.json")
sol = solve(sc)

sol.revenue()                       # (выручка A, выручка B)
sol.revenue(seats_a=30, seats_b=50) # из другого начального состояния
sol.best_price(node=3, seats_a=40, seats_b=44, opponent_level=11)   # уровень цены ходящего
sol.response_table(node=3, seats_a=40, seats_b=44)  # ответ на каждую цену соперника
print(format_path(play(sol)))       # траектория цен
monte_carlo(sol, 20000)             # проверка выручки розыгрышем
```

`best_price` для соперника — это и есть **прогноз его цены**: «если я поставлю такую цену, он ответит так».

Сохранённые результаты (`--save file.npz`):
* `policy[k, cA, cB, j]` — уровень, который выберет ходящий в T_k при остатках (cA, cB)
  и уровне соперника j; `-1`, если у ходящего мест нет;
* `value_a`, `value_b` — ожидаемая выручка с узла T_k до вылета в том же состоянии
  (для k = 0 — если обе компании стартуют на уровне j);
* `revenue` — выручка (A, B) для заданного сценария.

`--csv` выгружает стратегии таблицей (удобно для небольших задач; на 150 местах это миллионы строк).

## Как это считается

Состояние перед ходом в узле T_k: **(остаток A, остаток B, цена соперника)**. Цена самого
ходящего не важна — он её всё равно меняет.

Идём от вылета назад. В T_N выручка 0. Для узла T_k, где ходит A:

```
для каждой цены i:
    Q_A(i) = цена_i · E[продажи A в периоде k] + E[V_A(k+1, новые остатки, цена соперника = i)]
    Q_B(i) = цена B · E[продажи B]             + E[V_B(k+1, ...)]
i* = наименьший i с максимальным Q_A
V_A(k, ·) = Q_A(i*),  V_B(k, ·) = Q_B(i*)
```

Для B — симметрично, B максимизирует свою Q_B. В T₀ хода нет: обе цены стартовые.

Ожидание по исходам периода считается одной формулой. При фиксированных ценах продажи A и B
независимы, поэтому E[V(остатки после периода)] = M_A · V · M_Bᵀ, где
M[c, c'] — вероятность, что из c мест останется c'. В режиме `exact` это просто сдвиг.

Число состояний: периоды × (места A + 1) × (места B + 1) × 24, на каждое перебирается 24 цены.

## Проверка корректности

* **Полный перебор** (`airprice/bruteforce.py`) — отдельная реализация «в лоб»: рекурсия по
  дереву игры, перебор всех цен и всех исходов продаж. Тесты сверяют с ним все значения и все
  ходы решателя на случайных малых задачах (до 3 мест, 4 цен, 4 периодов) в обоих режимах,
  на произвольных таблицах спроса и на MNL.
* **Монте-Карло** — розыгрыш 20 000 партий по найденным стратегиям; средняя выручка совпадает
  с расчётной в пределах погрешности.
* Тесты отдельных правил: при равенстве берётся меньшая цена; распроданная компания уходит
  и спрос переключается на `mono`; места сгорают; у распроданного ходящего нет хода.
* Тесты проверены «порчей» решателя: при намеренно внесённых ошибках (обратное правило
  равенства, нет ухода распроданной компании, перепутаны роли A/B, неверное продолжение)
  тесты падают.

## Скорость

Замер на 2-ядерной облачной машине, 24 уровня цены, 20 периодов:

| Места у каждой | `exact` | `poisson` |
|---|---|---|
| 50 | 1,5 с | 2,1 с |
| 150 | 28 с | 30 с |

Это укладывается в требования записки (≤ 10 с и ≤ 1 мин). Память на 150 местах — около 200 МБ.
